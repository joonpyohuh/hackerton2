# Marketing Intelligence Workspace 구현 계획

2026-10-10 저장소와 운영 Neon DB를 읽어 확인한 결과입니다.

## 현재 구현

- Next.js 16.4 / React 19 / Tailwind 4 / Pretendard를 유지합니다.
- Resolver → 질문별 정의·스키마·승인 사례 검색 → GPT SQL 생성 → PostgreSQL AST 검사 → 정의 준수 검사 → 별도 LLM 의미 검사 → 읽기 전용 실행 → 오류 피드백 재생성이 구현되어 있습니다.
- NDJSON 스트리밍과 최근 6턴의 질문 맥락, 한국어 확인 질문을 재사용합니다.
- 운영 DB에는 analytics 원본 테이블 7개와 semantic 저장 테이블 3개가 있습니다. 가입 고객은 50,000명, 가입일은 2025-02-01~2025-04-01입니다. 현재 날짜 기준 최근 기간을 조회하면 데이터 범위 밖입니다.
- 정의 118개: 공식 지표 3개, 후보 지표 8개(원천 부족 1개 포함), 차원 6개, 업무·컬럼 용어 101개입니다. 후보 지표를 공식 지표로 표시하지 않습니다.
- 지표 CRUD, 실행 로그, 담당자 승인 사례 검색은 있지만 사용자 계정·분석 소유권·협업 검토 상태·공유 권한은 없습니다. 기존 편집·승인 API가 공개되어 있습니다.
- RAG는 의미 판정 + 문자열·별칭 검색입니다. 임베딩 검색이 구현되었다고 표시하지 않습니다.
- 기존 승인 사례는 전체 Semantic revision에 묶여 있습니다. 스키마 버전도 확인하도록 보완합니다.

## 변경 사항

1. 밝은 회색 배경, 흰 카드, 파란색 CTA, 큰 제목, 정돈된 여백을 사용하는 토스 스타일의 한국어 업무 화면으로 변경합니다. 사이드바와 결과 중심 레이아웃, 필요할 때 여는 분석 근거 패널을 제공합니다.
2. 공식 정의와 실제 데이터 범위를 API로 읽어 추천 질문·키워드를 제공합니다. 후보 지표와 관측 범위 밖 기간은 이유를 표시합니다. 시청시간 단위를 임의로 환산하지 않습니다.
3. 분석 결과는 KPI·막대·기간 추이·표를 데이터 형태에 따라 표시합니다. 요약은 실제 반환 숫자에서만 생성하고 인과관계나 전월 차이를 만들어내지 않습니다.
4. 계정과 DB 세션을 도입합니다. 역할은 서버 DB에서 읽고, 마케터는 자신의 분석과 공유된 분석에 접근하며 분석가는 검토 요청과 공식 정의를 관리합니다. 역할 선택 버튼으로 권한을 부여하지 않습니다.
5. 결과·SQL·정의 버전·검증 이력의 스냅샷을 저장합니다. 검토 요청/검토 중/수정 요청/승인 완료/검토 반려 상태와 의견·수정 SQL 제안 이력을 보존합니다. 수정 SQL을 검증 없이 실행하거나 승인 사례로 등록하지 않습니다.
6. 마케터는 정의 수정안을 제출하고 분석가가 현재 버전을 확인해 승인합니다. 정의 원본 버전은 별도 테이블에 보존하며 승인된 수정안만 공식 정의에 반영합니다.
7. 공유는 로그인한 같은 워크스페이스 사용자에게만 허용합니다. 개별 고객 식별자가 담긴 결과는 공유를 차단합니다. CSV는 분석 접근 권한을 확인하고 수식 실행 문자를 이스케이프합니다.

## DB 마이그레이션

`004_workspace.sql`은 기존 analytics 데이터를 수정하거나 삭제하지 않습니다.

- `workspace.users`: 계정, 비밀번호 해시, 서버 역할.
- `workspace.sessions`: 세션 토큰 해시, 만료 시각.
- `workspace.login_attempts`: 로그인 시도 제한.
- `workspace.analyses`: 분석 소유자, 원본 응답, 정의 스냅샷, 제목, 저장 여부, 내부 공유, 검토 상태, 스키마 버전.
- `workspace.review_events`: 요청·상태 변경·의견·수정 SQL·검토자 이력.
- `workspace.definition_changes`: 정의 변경 제안, 기준 버전, 검토 결과.
- `semantic.definition_versions`: 정의별 과거 버전. 기존 정의를 초기 보관하고 변경 트리거로 기록.
- `semantic.agent_runs.schema_version`: 승인 사례가 적용 가능한 실제 스키마 지문.

앱 계정에는 workspace와 semantic 저장 권한을 부여하고, 분석 SQL 실행 계정에는 analytics 읽기 권한만 유지합니다. 과거 공개 실행 로그에는 소유자를 임의로 배정하지 않습니다.

## 구현 순서와 완료 확인

1. 서버 인증·권한·마이그레이션 및 운영 DB 구조 확인.
2. 메인 화면·키워드 API·결과 시각화·근거 패널.
3. 분석 저장·내부 공유·CSV·검토 요청·분석가 검토.
4. 지표 사전·정의 수정 제안·버전 보존·승인 사례의 스키마/정의 버전 검사.
5. 역할별 접근 거부, 검토 상태, CSV, 키워드, 기존 Harness 회귀 테스트 및 빌드.
6. GitHub push, Vercel 운영 반영, 실제 운영 URL 확인. Git 연결과 모노레포 Root Directory가 맞는지도 점검.

## 범위와 한계

현재 데이터는 해커톤 OTT 코호트입니다. 기업 SSO, 이메일 초대 발송, 다중 기업 분리, 실시간 데이터 수집은 이번 구현에 포함하지 않습니다. 계정은 분석가가 발급하며 초기 분석가 자격은 저장소에 올리지 않는 로컬 파일로 전달합니다. 데이터 최신일은 원천 관측일이며 DB 연결 시각을 데이터 업데이트 시각으로 표현하지 않습니다.
